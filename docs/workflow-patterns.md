# 跨项目工作流经验

以下是从多篇论文修订及不同层级课题申报中提炼的方法，不含项目原文和研究数据。

## 图形：先确认关系，再决定形状

论文机制图需要区分“理论因果”“研究步骤”“测量维度”和“证据来源”。箭头不能同时承担几种含义。申报书的总体图负责研究主线，子研究图负责可执行的任务分解。每幅图都应能对应到一段明确的正文和一项输出。

同组图共享画布宽度与边距，同角色框保持同宽。优先增加图高、调整换行或压缩文字，避免把字缩到插入后不可读。框内文字整体居中，标题与正文作为一组计算位置；80%—88%的限制方向占用率作为紧凑排版参考，不能靠拉伸字形追求机械填满。

需要“1:1重绘并翻译”时，先建立原图元素、坐标和连接线清单。翻译后文字变长应在原框内换行或适当调字号，原有线条、锚点、分组关系保持不变。生成 SVG 和 PNG 预览；PPT 中若要逐元素编辑，应交付原生形状而非只嵌入一张 SVG。

## 文献：将检索、核验、入库、引用分开留证

Scholar 候选记录应保存精确匹配状态和检索时间，引用次数只是辅助筛选信息。DOI 核验区分在线首发时间、正式卷期时间、页码和文章编号；复合姓、机构作者以及更正/撤稿状态需要依据来源核对。

修订时优先修改已引用条目的元数据，保留其 Zotero key；新建相似条目可能让 Word 继续指向旧记录。删除引用时处理整个字段。多文献字段本身是合法的；只有与目标编辑方式不匹配、隐藏条目造成混乱或用户要求拆分时才拆分。

按字段边界审计，不能把“包含字段的段落数”当成“字段数”。同一段落可能有多个字段，bibliography 字段则可能跨多个段落。优先用真实 URI 标识条目，引用的显示编号和本地数字 ID 不代表同一件事。

宏返回无错误与 Zotero 完成更新是两个事件。刷新后重新检查引用与参考文献对应关系；需要证明现场更新时，可在可丢弃副本上修正一处过时的显示文本，观察 Zotero 是否恢复正确内容，随后重新核验最终文件。

## 申报：让研究设计可追踪

读取当年通知和模板后，建立“指南要求—现实问题—研究问题—研究任务—方法数据—验证方式—预期成果”矩阵。不同申报层级改变的是对象、资源和决策接口，不能简单替换地域名称。

并列子研究应有共同的比较维度；递进子研究应说明上一项产出如何成为下一项输入。总体技术路线图、各子研究图和正文使用一致的模块名与顺序。图中文字的篇幅也要纳入模板规定的统计口径。

当材料只支持研究计划时，用“拟收集、拟检验”表述。既有经验、访谈、理论饱和和统计结果必须对应真实记录，不能为让框架完整而补造。对匿名活页，应同时检查正文、图片、批注、修订和文档属性中的身份线索。
